<h1 align="center">DSH 插件市场更新助手</h1>

<p align="center">
  <b>为了解决插件市场不能更新自己的问题，我们决定再安装一个插件。</b><br />
</p>
<br>

## 这是什么东西

事情是这样的。

有一天我打开 DSH 插件市场，看见「更新插件市场」

然后市场更新到一半，把自己卸载了。

```text
插件市场：在更新前，我要先把旧的我卸载掉。
我：嗯嗯，然后呢？
插件市场：棍母
我：？
```

于是，这个插件诞生了。

它不是什么智能插件。它只负责把旧的插件市场卸载，然后把新的插件市场装上去。

**插件市场负责逛街，更新助手负责更新市场，分工明确。**

> 本项目针对的是 `dshmarket` 的这类更新场景，不代表所有版本或所有 DSH 部署都有这个问题。哪天市场自己修好了，这个插件就可以光荣退休~

## 怎么用

打开：

**设置 → 市场更新助手 → 更新插件市场**

点击，然后等。

```text
检查 npm 最新稳定版
        ↓
已经最新？那就下班。
        ↓ 不是
卸载旧版市场（助手：我还在）
        ↓
安装新版市场（助手：我真的还在）
        ↓
核对版本，汇报结果
```

需要重启时会告诉你，**不会突然替你把 DSH 关了**。~~毕竟我们是更新助手，不是重启助手。~~

## 安装

### 从 npm 安装（包发布后）

在 DSH 自带的插件管理界面，使用包名安装：

```text
dshmarket-update-helper
```


也可以让 DSH 里的 Agent 帮忙：

> 请使用 plugin_manager 安装 bundle：dshmarket-update-helper。

### 从源码安装

把项目下载到本地，在 DSH 插件管理器中将**项目目录的绝对路径**作为本地 bundle 安装。

**本地安装可能直接引用该目录，装完别把源码删了。** 


## ❓ 常见灵魂拷问

### 为什么为了更新一个插件，还要安装另一个插件？

因为插件不能在把自己卸载之后，继续努力工作。

所以有了这个朴素的想法。

### 那这个更新助手以后怎么更新？

它不像插件市场那样自己更新自己，原则上可以由市场或 DSH 自带的插件管理器处理。

~~暂时没有开发「市场更新助手更新助手」的想法。~~

~~**嗯，暂时。**~~

### 已经是最新版，点了会怎样？

检查一下，然后告诉你不用更新。

放心，不会为了证明自己的价值，先把插件市场卸了再装回来。

### 更新失败怎么办？

看助手里的「操作详情」。如果旧版恢复成功，会明确显示；如果恢复也失败，请使用 DSH 自带的插件管理器重新安装 `dshmarket`。

别去找已经被卸载的市场帮你装市场。我们就是为了打破这个循环才来的。

### 市场以后没有这个问题了怎么办？

卸载本插件，然后祝它前程似锦。

毕竟一个好补丁的终点，是不再需要这个补丁 ⦁ ⩊ ⦁

## 开发

没有额外运行时依赖，没有构建步骤。项目的复杂度主要集中在「为什么需要这个东西」上。

```sh
npm test
```

也可直接运行检查：

```sh
node --check index.js
node --check client.js
node test/updater.test.js
```
